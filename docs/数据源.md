# 数据源接入说明

「数据源」模块（`/datasources`，仅 `branch_admin` 可见）用于接入外部数据库 / 搜索引擎 / 向量库，AI 分析引擎（Python `codeact` sidecar）可跨数据源执行查询。

## 支持的数据源一览

共 **15 种**，类型由 `lib/db/schema.ts` 的 `DATA_SOURCE_TYPES` 单一来源维护（DB schema / 前端 / API zod / codeact 分发四处自动同步）。

### 关系型 / SQL（走 SQLAlchemy）

|---|---|---|---|---|
| SQLite（独立文件） | `sqlite` | — | 内置 `sqlite3` | `数据库文件路径` 指向外部 `.db` |
| MySQL | `mysql` | 3306 | pymysql | |
| PostgreSQL | `postgresql` | 5432 | psycopg2 | |
| SQL Server | `sqlserver` | 1433 | pymssql | |
| Oracle | `oracle` | 1521 | **oracledb**（thin 模式） | 需填 `Service Name` |
| DB2 | `db2` | 50000 | **ibm_db** | ⚠️ 需 DB2 clidriver |

### 搜索引擎

| 类型 | 标识 | 说明 |

## 向量检索统一接口

各向量库在 codeact 沙箱内统一暴露 `vector_search()`，签名与返回结构一致（`query_vector` 为已 embedding 的 `list[float]`，embedding 由 Agent 侧生成）：

```python
vector_search(collection_name_or_table, query_vector, top_k=10, output_fields=None)
# -> [{ "id": ..., "score": ..., ...元数据字段 }]
```

**score 语义差异**（需注意）：

- `Milvus` / `Qdrant` / `Weaviate`：**相似度**，越大越近。
- `Chroma` / `pgvector`：**距离**，越小越近（pgvector 用 `<=>` 余弦距离 / `<->` 欧氏距离 / `<#>` 内积，通过 `metric` 参数选择）。

## Oracle / DB2 客户端依赖

Python 驱动已随 `requirements.txt` 安装，但实际连库仍需外部系统客户端：

| 数据库 | 驱动 | 外部依赖 |
|---|---|---|
| Oracle | `oracledb`（python-oracledb） | **thin 模式无需客户端**（默认）；thick 模式才需 Oracle Instant Client（`libclntsh`） |
| DB2 | `ibm_db` | **必须** IBM DB2 clidriver（`libdb2`），安装后设 `IBM_DB_HOME` 指向 clidriver 目录 |

> 代码里 Oracle 使用 `oracle+oracledb://` 方言（thin 模式），绝大多数场景开箱即用；DB2 需目标环境预置 clidriver。

## 本地起库验证（Docker）

本项目已提供统一编排 `docker-compose.databases.yml`（`name: bank-datasources`）：

```bash
# 轻量组（默认）：MySQL / pgvector / Elasticsearch / Qdrant / Weaviate / Chroma / Milvus
docker compose -f docker-compose.databases.yml up -d

# 重量组（大镜像 + 首次启动慢，建议逐个测）：SQL Server / Oracle / DB2
docker compose -f docker-compose.databases.yml --profile heavy up -d sqlserver
docker compose -f docker-compose.databases.yml --profile heavy up -d oracle
docker compose -f docker-compose.databases.yml --profile heavy up -d db2
```

| 服务 | 宿主端口 | 账号 / 密码 | 备注 |
|---|---|---|---|
| MySQL | 3306 | root / demo123 | 库 `corp_credit` |
| pgvector | 5434 | postgres / demo123 | 库 `vector_demo`，PG16 + vector 0.8 |
| Elasticsearch | 9200 | 无认证 | 单节点，Xmx 512m |
| Qdrant | 6333 | 无认证 | |
| Weaviate | 8080 / 50051 | 匿名 | v1.27（需 v4 client） |
| Chroma | 8000 | 无认证 | |
| Milvus | 19530 | 无认证 | standalone（etcd+minio 内部网络） |
| SQL Server | 1433 | SA / Demo@12345 | amd64 模拟运行 |
| Oracle | 1521 | system / demo1234 | 服务名 `FREEPDB1` |
| DB2 | 50000 | db2inst1 / demo12345 | 库 `demo`，**仅 amd64**（Rosetta 模拟） |

> PostgreSQL 复用已有的 `bank-demo-postgres`（5432，`corp_profile`），不在此编排内。
> Oracle / DB2 / SQL Server 首次启动需 3–10 分钟初始化；测通后可用 `--profile heavy stop` 停掉省内存。

## 说明：部分镜像的 arm64 限制（Apple Silicon）

- SQL Server、DB2 官方镜像**无 arm64**，编排内已加 `platform: linux/amd64`，经 Rosetta 模拟运行（能跑、偏慢）。
- Oracle `gvenzl/oracle-free:23-slim` 提供 arm64，原生运行。

## 安全说明

- 数据源密码使用 **AES-256-GCM** 加密存储（`lib/security/encrypt.ts`），密钥由 `ENCRYPTION_KEY`（回退 `JWT_SECRET`）派生。
- 数据源配置仅 `branch_admin` 可增删改；查询执行受「数据范围 scope」约束（personal / branch / bank）。
